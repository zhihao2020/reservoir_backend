## 2. 关于 80 Pa，我会稍微修改你的表述

你说：

> “80 Pa 裂缝 σ 对真实实验室不成立。”

从当前 GitHub 证据看，还不能证明“实验室做不到 80 Pa”。

准确说法应该是：

> **80 Pa 目前没有真实仪器依据，并且与现有产品测量合同中的 2 kPa 不一致。**

当前正式 CSV 明确还是 2 kPa。

因此不能为了让 ES-MDA 过关，就把正式实验的 \(\sigma\) 从 2000 Pa 改成 80 Pa。

应该把问题变成一个实验设计问题：

$$
\boxed{
\text{measurement precision}
+
\text{excitation strength}
+
\text{sensor placement}
}
$$

共同决定 \(C_f\) 是否可辨识。

当前单点估算：

$$
\frac{\Delta P_{5\%C_f}}{\sigma_P}
=
\frac{80}{2000}
=0.04
$$

只有 \(0.04\sigma\)，确实非常弱。

我建议以后不要只看“80 Pa/2 kPa”这个单点指标，而正式增加一个 **Cf detectability gate**：

$$
D_{C_f}
=
\sqrt{
\Delta y_{C_f}^{T}
R^{-1}
\Delta y_{C_f}
}
$$

其中：

$$
\Delta y_{C_f}
=
H(F(1.05C_f))-H(F(C_f))
$$

它把所有：

* 压力测点
* 时间点
* 测量误差
* 传感器类型

统一算进去。

如果：

$$
D_{C_f}<1
$$

那就是整个实验连一个统计意义上的 \(1\sigma\) 变化都分辨不出来。

产品设计我建议至少要求：

$$
\boxed{D_{C_f,5\%}>2\sim3}
$$

这样比“把 sigma 调小直到 ES-MDA 过”科学得多。

# 4. 我又发现一个必须先修的问题：四真值扫描脚本现在可能是假的 sweep

这个比“还没有跑出结果”更值得注意。

现在：

`scripts/lab_v1_joint_sweep.py`

先调用：

```python
syn = make_lab_v1_face_twin(...)
```

这个函数默认：

$$
T_{mf}^{true}=2.0
$$

并且在构造 `SyntheticCase` 的过程中已经生成 synthetic observations。

但 sweep 后面才做：

```python
syn.theta_true = encode([cf, beta])
syn.twin.simulate(...)
```

然后直接：

```python
post = syn.twin.calibrate()
```

问题是：

**重新 `simulate()` 并没有重新生成 `experiment.observations`。**

也就是说 T1/T3 设：

$$
\beta_{mf}=0.5
$$

时，很可能观测数据仍然来自构造 twin 时默认的：

$$
\beta_{mf}=2.0
$$

于是这个 `{0.5,2}²` sweep 在逻辑上就不成立。

这个应该排在下一轮最前面修。

正确做法是让构造函数直接接受：

```python
make_lab_v1_face_twin(
    cf_true=cf,
    tmf_true=beta,
    ...
)
```

而不是事后修改 `theta_true`。

然后重新生成 observations。
