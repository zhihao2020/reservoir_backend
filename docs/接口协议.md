# reservoir-backend 通讯接口协议（协议 v2）

> **⛔ 冻结（FROZEN）**：本文档是自库版本 `0.4.0` 起冻结的权威 wire 协议，联调方式与
> 接口此后不再变化。对接方按本文档实现即可。任何改动都必须新起协议版本（v3），
> **不得在 v2 上静默修改**。

本文档是 `reservoir-backend` 进程与外部采集端 / 仪表盘之间的**权威 wire 协议**，与
`src/programs/protocol.py` 逐字节一致。对接方按本文档实现即可，无需读源码。

- **库版本**：`src.version.__version__`（当前 `0.4.0`）。
- **协议版本**：`PROTOCOL_VERSION = 2`（breaking，与 v1 不兼容）。
- **字节序**：一律**小端**（little-endian）。多字节类型用 `struct` 格式标注。
- **文本编码**：JSON 消息用 UTF-8。

三个角色、三个端口（另有可选控制端口）：

```
采集端 send_steps.py  --TCP-->  python -m src  --UDP:lab-->  仪表盘（对接方实现）
                                              --UDP:field--> 仪表盘（对接方实现）
                                              <--UDP:control-- (可选 RESEND)
```

---

## 1. TCP 入站（采集端 ↔ 后端，双向可靠）

TCP 是**长度前缀帧**流：每条帧 = 4 字节无符号长度 + 载荷。`length` 计数的是
`version(1) + msg_type(1) + payload(N)` 的字节数（即 `2 + len(payload)`）。

```
[u32 length][u8 version=2][u8 msg_type][payload ...]
```

控制消息 payload 为 **JSON(UTF-8)**，数据消息 payload 为**打包二进制**。

### 1.1 消息类型

| type | 名称 | 方向 | payload |
|---|---|---|---|
| 0x01 | HELLO | 后端 → 采集端 | JSON manifest（§1.2） |
| 0x02 | READY | 采集端 → 后端 | JSON `{version, ok, warnings}` |
| 0x03 | STEP | 采集端 → 后端 | 二进制（§1.3） |
| 0x04 | ACK | 后端 → 采集端 | JSON `{seq, time_s, accepted}` |
| 0x05 | NAK | 后端 → 采集端 | JSON `{seq, code, message}`（§1.5） |
| 0x06 | BYE | 双向 | 空 |

流程：采集端 `connect` → 后端发 **HELLO** → 采集端发 **READY** → 逐拍发 **STEP** /
收 **ACK**/**NAK** → 采集端发 **BYE** 关闭。连接长期复用（不要每拍重连），双方开
`TCP_NODELAY`。对端断开后后端只重新 `accept`，已累积的历史保留在进程内。

### 1.2 HELLO manifest（JSON）

后端在 `accept` 后立即发送。字段：

```json
{
  "protocol_version": 2,
  "library": "reservoir-backend",
  "library_version": "0.4.0",
  "n_probes": 16, "n_wells": 5,
  "probe_ids": ["P_5_5_5", "..."], "probe_xyz": [[0.09, 0.09, 0.21], "..."],
  "well_ids": ["INJ", "..."],   "well_xyz": [[0.15, 0.15, 0.29], "..."],
  "grid": {"nx": 60, "ny": 60, "nz": 60, "origin": [0,0,0], "extent": [0.30,0.30,0.30],
           "n_cells": 216000, "cell_order": "k*ny*nx + j*nx + i", "shape_ijk": [60,60,60]},
  "similarity": {"lambda_x": ..., "c_v": ..., "c_lc": ..., "c_t": ..., "c_qv": ...,
                 "model": {"length_m": 0.30, "width_m": 0.30, "height_m": 0.30, "volume_m3": 0.027}},
  "quantity_enum": {"1": "pressure", "2": "sw", "3": "so", "4": "sg"},
  "quantity_units": {"1": "Pa", "2": "", "3": "", "4": ""},
  "well_kind_enum": {"1": "bhp", "2": "inject_co2", "3": "prod_water", "4": "prod_oil", "5": "prod_gas"}
}
```

`probe_ids`/`well_ids` 的顺序即下标顺序：STEP 里的 `probe_index` / `well_index` 就是这
个数组的序号（**不带坐标、不带井号**）。

### 1.3 STEP 载荷（二进制）

```
[u32 seq][f64 time_s][u16 n_probe_records][u16 n_well_records]
  然后 n_probe_records 条测点记录 + n_well_records 条注采记录
```

每条记录 11 字节（`<HBd`）：`[u16 index][u8 code][f64 value]`。

- `seq`：采集端自增的序号，后端原样回填到 ACK/NAK，用于把回执对应到某一拍。
- `time_s`：秒。必须大于上一拍；**等于上一拍则覆盖该拍**；小于上一拍 → NAK `bad_time`。
- 一帧内测点/井**可稀疏**：只带这一拍有变化的量，没传到的量保持空（NaN）。

测点 `quantity`（`code`）：

| code | 量 | 单位 |
|---|---|---|
| 1 | 压力 | Pa |
| 2 | 水饱和度 Sw | — |
| 3 | 油饱和度 So | — |
| 4 | 气饱和度 Sg | — |

注采 `kind`（`code`），流量填**正数**，种类决定注还是采：

| code | 量 | 单位 | 内部符号 |
|---|---|---|---|
| 1 | 井底压力 | Pa | 原样 |
| 2 | 注入（CO₂） | m³/s | 总流量、气流量为正 |
| 3 | 产水 | m³/s | `qw` 为负 |
| 4 | 产油 | m³/s | `qo` 为负 |
| 5 | 产气 | m³/s | `qg` 为负 |

### 1.4 ACK（JSON）

```json
{"seq": 3, "time_s": 2592000.0, "accepted": true}
```

### 1.5 NAK 与错误码

```json
{"seq": 3, "code": "bad_time", "message": "time 2592000.0 is earlier than last ..."}
```

| code | 含义 |
|---|---|
| `bad_version` | 协议版本不匹配 |
| `not_ready` | 未 READY 就发 STEP |
| `bad_sequence` | seq 异常（保留） |
| `bad_time` | 时间倒退 |
| `bad_index` | 测点/井下标越界 |
| `bad_quantity` | 未知测点量 |
| `bad_kind` | 未知注采种类 |
| `bad_data` | 观测无有效值 / 其它反演前置校验失败 |
| `truncated` | 帧或载荷截断 |

## 2. UDP 出站（后端 → 仪表盘，单向，带可靠性）

每个数据报自含头，载荷小端：

```
[u16/2s "RB"][u8 version=2][u8 msg_type][u32 stream_id][u32 seq][payload ...]
```

`stream_id` 每进程唯一（当前为 `os.getpid()` 低 32 位）；`seq` 在该流内单调递增。
接收端靠 `seq` 检测丢包/乱序，靠每块 CRC32 与 END 的计数/整体 CRC 校验完整性。

### 2.1 消息类型

| type | 名称 | payload |
|---|---|---|
| 0x01 | MANIFEST | JSON（§2.2），流起始发送 |
| 0x02 | FIELD | 二进制场块（§2.3） |
| 0x03 | RESULTS | JSON 井/测点结果（§2.4） |
| 0x04 | END | 二进制 `[u32 total_datagrams][u32 stream_crc]` |
| 0x05 | RESEND | 空（仪表盘 → 后端控制端口，请求重发最近一段） |

一次完整流 = MANIFEST + 若干 FIELD + RESULTS + END。每收到一拍，后端把**当前滑动窗口**的
场再发一遍（先 MANIFEST 再全部 FIELD/…/END）。在线模式只保留最近 2 拍（滑动窗口，当前 + 上一拍），
所以 `MANIFEST.times` 是**滑动窗口**（新拍到达时最老的时间被挤出，`times` 整体前移）。
岩石反演（k/φ）在后台线程计算，其新值在**下一拍**（或控制口 RESEND）随流更新。

### 2.2 MANIFEST（JSON）

```json
{
  "protocol_version": 2, "library": "reservoir-backend", "library_version": "0.4.0",
  "scale": "lab",              // "lab" 或 "field"
  "nx": 60, "ny": 60, "nz": 60,
  "origin": [0,0,0], "extent": [0.30,0.30,0.30], "n_cells": 216000,
  "cell_order": "k*ny*nx + j*nx + i", "shape_ijk": [60,60,60],
  "times": [2592000.0, "..."],
  "fields": [
    {"field_id": 0, "name": "p", "unit": "Pa"},
    {"field_id": 1, "name": "sw", "unit": ""},
    {"field_id": 2, "name": "so", "unit": ""},
    {"field_id": 3, "name": "sg", "unit": ""},
    {"field_id": 4, "name": "phi", "unit": ""},
    {"field_id": 5, "name": "k", "unit": "m2"}
  ],
  "similarity": { "...": "同 HELLO" },
  "probes": [{"id": "P_5_5_5", "x_m": 0.09, "y_m": 0.09, "z_m": 0.21}, "..."],
  "wells":  [{"id": "INJ", "kind": "injector", "x_m": 0.15, "...": "含 x2/y2/z2"}]
}
```

### 2.3 FIELD 场块（二进制）

```
[i32 t][u8 field_id][i32 offset][i32 n_values][f64 × n_values][u32 crc32]
```

`crc32` 是前 `n_values × 8` 字节（**不含头**）的 CRC-32。同一 `(t, field_id)` 拆成多个
块时按 `offset` 拼接；`offset` 是单元序号，每块 ≤ 7000 个值。

`field_id` 枚举与单位：

| field_id | 量 | 单位 |
|---|---|---|
| 0 | 压力 `p` | Pa |
| 1 | 水饱和度 `sw` | — |
| 2 | 油饱和度 `so` | — |
| 3 | 气饱和度 `sg` | — |
| 4 | 孔隙度 `phi` | — |
| 5 | 渗透率 `k` | m² |

### 2.4 RESULTS（JSON，井/测点级结果）

```json
{
  "n_times": 12, "times_s": [2592000.0, "..."],
  "probes": [
    {"id": "P_5_5_5", "cell": 1234,
     "observed": {"pressure_pa": [19101100.0, "..."], "sw": [...], "so": [...], "sg": [...]},
     "reconstructed": {"pressure_pa": [...], "sw": [...], "so": [...], "sg": [...]},
     "rmse": {"pressure_pa": 13209.0, "sw": 0.0, "so": 0.005, "sg": 0.095}}
  ],
  "wells": [
    {"id": "INJ", "kind": "injector", "n_cells": 3,
     "bhp_reconstructed_pa": [19325000.0, "..."],
     "sw": [...], "so": [...], "sg": [...],
     "control": {"pw_pa": [...], "q_m3s": [...], "qw_m3s": [...], "qo_m3s": [...], "qg_m3s": [...]}}
  ],
  "diagnostics": {"mass_residual_rel": ..., "holdout": {...}}
}
```

- `observed` / `reconstructed` / `control` 里缺失的量用 `null` 表示。
- `bhp_reconstructed_pa` = 重构压力场在该井**完井单元**上的逐拍均值；井饱和度同理。
- `control` 是**输入**控制回填（反演把流量当输入，不另产重构流量；全局一致性看
  `diagnostics.mass_residual_rel`）。
- 时间索引同 `MANIFEST.times`。

### 2.5 END 与完整性校验

```
[u32 total_datagrams][u32 stream_crc]
```

- `total_datagrams` = 本流所有数据报个数（含 MANIFEST / RESULTS / END 本身）。
- `stream_crc` = 所有 FIELD 值字节按发送顺序 `(t, field_id, offset)` 的**运行 CRC-32**。

接收端必须做三件事，任一不满足即判 `incomplete` 并报错（不得静默出数）：
1. `seq` 连续、个数 = `total_datagrams`；
2. 每个 FIELD 块的 CRC 通过；
3. 每个 `(t, field_id)` 的块按 `offset` 连续覆盖 `[0, n_cells)`，整体 CRC 等于
   `stream_crc`。

## 3. 单元排序（reshape 规则，关键）

全场 flat 数组的单元索引是 **C 序，z 最慢、x 最快**：

```
cell = k * ny * nx + j * nx + i
```

还原成 3D 数组（轴 0 = z/k，轴 1 = y/j，轴 2 = x/i）：

```python
field3d = flat.reshape((nz, ny, nx))     # nz, ny, nx 取自 MANIFEST
```

`MANIFEST.cell_order` 与 `MANIFEST.shape_ijk` 已写明这一约定，接收端据此 reshape，
无需硬编码。

## 4. 矿场 / 实验尺度

- `--lab-port` 发实验尺度（模型 0.30 m 立方）。
- `--field-port` 发按 `similarity` 换算后的矿场尺度（如 300 m × 300 m × 30 m）。
- **矿场尺度只缩放网格几何与时间**：`p`(Pa)、`sw/so/sg`(无量纲)、`phi`(无量纲)、
  `k`(m² 物性) 的**场值不变**（相似准则下压力/饱和度/物性逐点相等，仅几何与时间
  缩放）。`MANIFEST.scale` 标 "field"，`times` 已乘 `c_t`。

相似比定义与换算公式见 [`相似换算.md`](相似换算.md)。

## 5. 离线文件 I/O（`python -m src case.yaml -o DIR`）

离线模式读 `case.yaml` + 四个 CSV，写 `DIR/`：

| 文件 | 内容 |
|---|---|
| `case.yaml` | 网格、测点/井文件引用、反演模型、黑油参数、相似比 |
| `probes.csv` | `id,x_m,y_m,z_m` |
| `wells.csv` | `id,kind,x_m,y_m,z_m,x2_m,y2_m,z2_m` |
| `observations.csv` | `time_s,probe,quantity,value,unit`（quantity: pressure/sw/so/sg） |
| `series.csv` | `time_s,well,pw_pa,q_m3s,qw_m3s,qo_m3s,qg_m3s` |

输出：

| 文件 | 内容 |
|---|---|
| `fields.npz` | 实验尺度场：`time,p,sw,so,sg,phi,k,k_md,nx,ny,nz,origin,extent,scale` |
| `fields_field.npz` | 矿场尺度场：同上但 `time/origin/extent` 已换算，`scale="field"` |
| `p.npy` 等 | 每个场一个 `(n_times, n_cells)` 数组（`p/sw/so/sg/phi/k/k_md`） |
| `mesh.csv` | 测点/井 → 单元映射 `kind,id,x,y,z,i,j,k,cell` |
| `wells.csv` | 井控制回放 `time_s,well,kind,pw_pa,q_m3s,qw,qo,qg` |
| `wells_field.csv` | 矿场尺度等效井位（非等比例时） |
| `summary.json` | 汇总：`n_cells,phi_mean,k_md_mean,similarity,...` |
| `validation.json` | 反演诊断：`mass_residual_rel,holdout,...` |
| `results.json` | 井/测点级结果（同 UDP RESULTS，§2.4） |

`case.yaml` 完整字段说明见 [`案例库.md`](案例库.md) 与 `src/core/lab_case.py`。
