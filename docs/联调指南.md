# 联调指南（完整使用说明）

本文档是一份**从零到联调跑通**的完整说明：先把示例案例跑通（离线 + 在线），再把你自己的
采集端 / 数据大屏接上来。协议细节见 [`接口协议.md`](接口协议.md)，案例清单见
[`案例库.md`](案例库.md)。

---

## 1. 前置条件

- Linux（或 Windows）主机，Python ≥ 3.11。
- 依赖：`numpy`、`scipy`、`PyYAML`。安装：

```bash
pip install -e ".[dev]"          # 从源码安装（含 pytest）
# 或最小安装
pip install numpy scipy pyyaml
```

## 2. 30 秒自检

```bash
python -m src --version              # reservoir-backend 0.4.0
python scripts/verify_examples.py    # 逐个案例跑通，应打印 "all examples verified"
python -m pytest                     # 33 passed（可选）
```

`verify_examples.py` 会把 5 个快案例走一遍离线反演并校验产物，把 60³ 的 `online` 案例做
解析检查。这一步通过，说明示例库是完整可用的。

## 3. 案例库一览

| 案例 | 目录 | 网格 | 模型 | 耗时 | 用途 |
|---|---|---|---|---|---|
| **秒级联调** | `small/` | 8×8×8 | black_oil_3phase | 秒级 | **首次跑通、TCP/UDP 联调** |
| 2D | `twod/` | 30×30×1 | black_oil_3phase | 秒级 | 单层切片调试 |

## 4. 离线跑通（文件 → 文件）

不涉及网络，验证"读 YAML/CSV → 反演 → 落盘"这一整条链路。

```bash
python -m src examples/small/case.yaml -o results/small
```

**预期输出**：一行 JSON 汇总，含 `"output": "results/small"`、`"nx": 8`、`"n_cells": 512`、
`"n_times": 3`、`"similarity": {...}` 等。

**产物**（`results/small/`，共 15 个文件）：

| 文件 | 内容 |
|---|---|
| `fields.npz` / `fields_field.npz` | 实验/矿场尺度场（含 `time,p,sw,so,sg,phi,k,k_md,nx,ny,nz,origin,extent,scale`） |
| `p.npy` `sw.npy` `so.npy` `sg.npy` `phi.npy` `k.npy` `k_md.npy` | 每个场一个 `(n_times, n_cells)` 数组 |
| `mesh.csv` | 测点/井 → 单元映射 |
| `wells.csv` / `wells_field.csv` | 井控制回放 / 矿场尺度等效井位 |
| `summary.json` | 汇总（`phi_mean`、`k_md_mean`、相似比、单位换算系数） |
| `validation.json` | 反演诊断（质量守恒残差、LOOCV、holdout） |
| `results.json` | **井/测点级结果**（观测 vs 重构 + RMSE、井底压力、控制回填） |

快速看结果：

```bash
python -c "import json; d=json.load(open('results/small/results.json')); \
print(d['probes'][0]['rmse']); print(d['wells'][0]['bhp_reconstructed_pa'])"
```

## 5. 在线跑通（TCP 入 + UDP 出）

三个角色、三个端口。测点和注采走 TCP，反演结果走两路 UDP。

```
采集端 send_steps.py ──TCP:9000──▶ python -m src ──UDP:9001(lab)──▶ 仪表盘 recv_fields.py
                                              ──UDP:9002(field)─▶ 仪表盘 recv_fields.py
```

### 5.1 四个终端

**启动顺序：先收 UDP，再起反演，最后发 TCP**（否则第一拍结果会在接收端起来前丢掉）。

```bash
# 终端 1：实验尺度接收
python examples/online/recv_fields.py --port 9001 --label lab

# 终端 2：矿场尺度接收
python examples/online/recv_fields.py --port 9002 --label field

# 终端 3：反演（用秒级 small 案例，--window 24 --invert-every 2 是长会话性能参数）
python -m src examples/small/case.yaml --tcp-port 9000 --ip 127.0.0.1 \
    --lab-port 9001 --field-port 9002 --window 24 --invert-every 2

# 终端 4：采集端（发测点 + 注采）
python examples/online/send_steps.py --host 127.0.0.1 --port 9000 \
    --probes examples/small/probes.csv --wells examples/small/wells.csv \
    --observations examples/small/observations.csv --series examples/small/series.csv
```

### 5.2 各终端预期输出

**终端 3（后端）**启动后先打印一行配置 JSON：

```json
{"mode": "tcp", "protocol_version": 2, "tcp_port": 9000, "ip": "127.0.0.1",
 "lab_port": 9001, "field_port": 9002, "control_port": null, "window": 24,
 "invert_every": 2.0, "n_probes": 4, "n_wells": 2, "nx": 8, ...}
```

连接与逐拍：

```json
{"tcp": "connected", "peer": "127.0.0.1:xxxxx"}
{"tcp": "ready", "client_version": 2, "ok": true}
{ ...summary JSON，每拍一次... }
{"tcp": "disconnected"}
```

**终端 4（采集端）**：

```
HELLO v2: n_probes=4 n_wells=2 grid=8x8x8
ACK seq=0 time_s=2592000.0
ACK seq=1 time_s=5184000.0
ACK seq=2 time_s=7776000.0
```

**终端 1（实验尺度）**：

```
[lab #1] scale=lab nx=8 ny=8 nz=8 extent_m=[0.3, 0.3, 0.3] n_times=3
  cell_order=k*ny*nx + j*nx + i shape_ijk=[8, 8, 8] times_s=[2592000.0, ...]
  p: shape=(3, 512) mean=1.9104e+07
  ...
  reshape(p) -> (8, 8, 8)
  results:
    well INJ (injector): n_cells=1 last_bhp=1.9xxxe+07
    probe P_corner_1: p_rmse=...
```

终端 2（矿场尺度）类似，但 `scale=field`、`extent_m=[300.0, 300.0, 30.0]`、`times_s` 已乘时间
相似比（`n_times` 不变，**场值不变**）。

### 5.3 验证要点

1. 终端 4 每拍都是 `ACK`（不是 `NAK`）。
2. 终端 1/2 的 `shape_ijk` 正确、每个场 `shape=(n_times, n_cells)`、`reshape(p)` 成功。
3. 终端 1/2 的 `results:` 有井级 `last_bhp` 和测点级 `p_rmse`/`sg_rmse`。

## 6. 换成你自己的采集端 / 大屏

### 6.1 采集端（TCP 发数据）

对照 [`接口协议.md` §1](接口协议.md) 实现。关键点：

- **连一次，长期复用**，不要每拍重连；开 `TCP_NODELAY`。
- 后端 `accept` 后先发 **HELLO**（JSON，含 `n_probes/n_wells/probe_ids/well_ids/枚举/单位`），
  采集端据此校验**下标顺序**。
- 采集端回 **READY** `{"version":2,"ok":true}`，然后逐拍发 **STEP**、等 **ACK/NAK**。
- STEP = `[u32 seq][f64 time_s][u16 n_probe][u16 n_well][记录...]`，每条记录
  `[u16 index][u8 code][f64 value]`（11 字节，小端）。
- `quantity`（测点）：1 压力 Pa、2 Sw、3 So、4 Sg。`kind`（井）：1 井底压力 Pa、
  2 注入 CO₂ m³/s、3 产水、4 产油、5 产气（**流量填正数**，种类决定注/采）。
- 参考实现：`examples/online/send_steps.py`；组包函数 `src.programs.protocol.pack_step` + `frame_tcp`。

### 6.2 大屏（UDP 收数据）

对照 [`接口协议.md` §2/§3](接口协议.md)。关键点：

- 报头 `[2s"RB"][u8 ver][u8 type][u32 stream_id][u32 seq]`；消息 MANIFEST / FIELD / RESULTS / END。
- 收到 MANIFEST 后按 `cell_order` / `shape_ijk` reshape：`flat.reshape((nz, ny, nx))`。
- 每收到一拍后端重发**当前滑动窗口**整段；`MANIFEST.times` 是窗口（会随新拍前移）。
- FIELD 带 CRC32、END 带总报数+整体 CRC；丢包/损坏会报 `incomplete`，用 `--control-port` 发
  RESEND 可让后端重发最近一段。
- 参考实现：`examples/online/recv_fields.py`；收流函数 `src.programs.udp.receive_fields`。

### 6.3 矿场尺度（`--field-port`）

矿场尺度**只缩放网格几何与时间**，`p/sw/so/sg/phi/k` 场值不变（相似准则）。若大屏要显示
矿场尺度的**等效井位**，看 `wells_field.csv` 或 UDP MANIFEST 里的 `similarity` 换算。

## 7. 长会话性能（数据太快怎么办）

见 §5.1 命令里的 `--window 24 --invert-every 2`：

- 实时路径（插值）每拍 O(网格数)，结果**立即**发 UDP；
- 岩石反演（k/φ）在**后台线程**，按 `--invert-every` 秒节流，不阻塞实时路径；其新值在
  **下一拍**（或 RESEND）随流更新；
- `--window N` 只保留最近 N 拍（默认 24），`--window 0` = 不限；
- 采集端**每拍等一个 ACK**，TCP 流控自动背压，数据不丢、不堆积。

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| NAK `bad_time` | 时间倒退 | `time_s` 严格递增（同值覆盖上一拍） |
| NAK `bad_index` | 下标越界 | 按 HELLO 的 `probe_ids`/`well_ids` 顺序编号 |
| NAK `bad_quantity`/`bad_kind` | 码不对 | 对照 §6.1 的枚举 |
| NAK `truncated` | 帧长度不符 | 检查小端 + struct 布局 |
| UDP `INCOMPLETE: …missing seq…` | 丢包 | 调大接收缓冲 / 用 `--control-port` RESEND |
| 仪表盘收到空场/全 NaN | 某拍只发了部分测点 | 至少 1 个有限压力 + 1 个有限饱和度 |
| 后端启动即报 `series_issues` | 离线缺观测 | 补 `observations.csv`，或加 `--tcp-port` 走在线 |

**单位**（内部全 SI）：压力 Pa（CSV `unit` 可写 MPa/kPa/bar/psi）、流量 m³/s（可用
`q_m3s` 或 `q`+`q_unit`）、渗透率 m²（`k0_md` 用 mD）、长度 m、时间 s。
