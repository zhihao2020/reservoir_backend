# 联调指南（完整使用说明）

从零把 [`example/`](../example/) 联调跑通：接收端 UDP 收场、后端反演、调用端 TCP 发 STEP。
协议细节见 [`接口协议.md`](接口协议.md)，案例字段见 [`案例库.md`](案例库.md)。
使用说明也写在 [`example/README.md`](../example/README.md)。

协议 v2 冻结不变（wire 接口未动）。

## 4. 在线联调（TCP 入 + UDP 出）

三个角色、三个端口。测点和注采走 TCP，反演结果走两路 UDP。本仓库在 `example/` 提供**接收端**、**后端**、**调用端**。

```
send_steps.py ──TCP:9000──▶ python -m src ──UDP:9001(lab)──▶ receive_fields.py
                                          ──UDP:9002(field)─▶ receive_fields.py
```

**启动顺序：先起接收，再起后端，再发 TCP**。

```bash
# 终端 1：接收端
python example/receive_fields.py --lab-port 9001 --field-port 9002

# 终端 2：后端（真实 GEM 数据，27 测点 / 5 井 / 120 拍）
python -m src example/case.yaml --tcp-port 9000 --ip 127.0.0.1 \
    --lab-port 9001 --field-port 9002

# 终端 3：调用端（读 example 时序，逐拍发 STEP）
python example/send_steps.py --host 127.0.0.1 --port 9000
```

`observations.csv`（120×27×4=12960 行）与 `series.csv`（120×5=600 行）是完整 10 年逐月数据；
`send_steps.py` 逐拍发 STEP、每拍等 ACK，120 拍会跑一小会儿。

### 各终端预期输出

**终端 1（接收端）**：

```
{"udp": "listening", "scale": "lab", "port": 9001}
{"udp": "listening", "scale": "field", "port": 9002}
{"scale": "lab", "nx": 15, "n_cells": 3375, "fields": ["k", "p", "phi", "sg", "so", "sw"], ...}
```

**终端 2（后端）**启动后先打印配置 JSON：

```json
{"mode": "tcp", "protocol_version": 2, "tcp_port": 9000, "ip": "127.0.0.1",
 "lab_port": 9001, "field_port": 9002, "control_port": null, "window": 2,
 "n_probes": 27, "n_wells": 5, "nx": 15, ...}
```

连接与逐拍：

```json
{"tcp": "connected", "peer": "127.0.0.1:xxxxx"}
{"tcp": "ready", "client_version": 2, "ok": true}
{ ...summary JSON，每拍一次... }
{"tcp": "disconnected"}
```

**终端 3（调用端）**：

```
HELLO v2: n_probes=27 n_wells=5 grid=15x15x15
ACK seq=0 time_s=...
ACK seq=1 time_s=...
...
```

`receive_fields.py` 在 `--lab-port` / `--field-port` 收到 MANIFEST + FIELD + RESULTS + END，
得到完整场（`(n_times, n_cells)` 的 `p/sw/so/sg/phi/k`），按 `shape_ijk` reshape 成 `(nz, ny, nx)`。

### 验证要点

1. 终端 3（调用端）每拍都是 `ACK`（不是 `NAK`）。
2. 后端配置 JSON 的 `window=2`、`n_probes=27`、`n_wells=5`、`nx=15`。
3. 接收端每个场 `shape=(n_times, n_cells)`、`reshape(p)` 成功。

## 5. 换成你自己的采集端 / 大屏

### 5.1 采集端（TCP 发数据）

对照 [`接口协议.md` §1](接口协议.md) 实现。关键点：

- **连一次，长期复用**，不要每拍重连；开 `TCP_NODELAY`。
- 后端 `accept` 后先发 **HELLO**（JSON，含 `n_probes/n_wells/probe_ids/well_ids/枚举/单位`），
  采集端据此校验**下标顺序**。
- 采集端回 **READY** `{"version":2,"ok":true}`，然后逐拍发 **STEP**、等 **ACK/NAK**。
- STEP = `[u32 seq][f64 time_s][u16 n_probe][u16 n_well][记录...]`，每条记录
  `[u16 index][u8 code][f64 value]`（11 字节，小端）。
- `quantity`（测点）：1 压力 Pa、2 Sw、3 So、4 Sg。`kind`（井）：1 井底压力 Pa、
  2 注入 CO₂ m³/s、3 产水、4 产油、5 产气（**流量填正数**，种类决定注/采）。
- 参考实现：`example/send_steps.py`；组包函数 `src.programs.protocol.pack_step` + `frame_tcp`。

### 5.2 大屏（UDP 收数据）

对照 [`接口协议.md` §2/§3](接口协议.md)。关键点：

- 报头 `[2s"RB"][u8 ver][u8 type][u32 stream_id][u32 seq]`；消息 MANIFEST / FIELD / RESULTS / END。
- 收到 MANIFEST 后按 `cell_order` / `shape_ijk` reshape：`flat.reshape((nz, ny, nx))`。
- 每收到一拍后端重发**当前滑动窗口**整段；`MANIFEST.times` 是窗口（会随新拍前移）。
- FIELD 带 CRC32、END 带总报数+整体 CRC；丢包/损坏会报 `incomplete`，用 `--control-port` 发
  RESEND 可让后端重发最近一段。
- 收流参考：`example/receive_fields.py`（调用 `src.programs.udp.receive_fields`）。

### 5.3 矿场尺度（`--field-port`）

矿场尺度**只缩放网格几何与时间**，`p/sw/so/sg/phi/k` 场值不变（相似准则）。若大屏要显示
矿场尺度的**等效井位**，看 `wells_field.csv` 或 UDP MANIFEST 里的 `similarity` 换算。

## 6. 长会话性能（数据太快怎么办）

在线模式内置了滑动窗口（2 拍）常量，无需配置：

- 实时路径（插值）每拍 O(网格数)，结果**立即**发 UDP；
- 岩石反演（k/φ）在**后台线程**，每拍触发，不阻塞实时路径；其新值在
  **下一拍**（或 RESEND）随流更新；
- 只保留最近 2 拍（当前 + 上一拍）；
- 采集端**每拍等一个 ACK**，TCP 流控自动背压，数据不丢、不堆积。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| NAK `bad_time` | 时间倒退 | `time_s` 严格递增（同值覆盖上一拍） |
| NAK `bad_index` | 下标越界 | 按 HELLO 的 `probe_ids`/`well_ids` 顺序编号 |
| NAK `bad_quantity`/`bad_kind` | 码不对 | 对照 §5.1 的枚举 |
| NAK `truncated` | 帧长度不符 | 检查小端 + struct 布局 |
| UDP `INCOMPLETE: …missing seq…` | 丢包 | 调大接收缓冲 / 用 `--control-port` RESEND |
| 仪表盘收到空场/全 NaN | 某拍只发了部分测点 | 至少 1 个有限压力 + 1 个有限饱和度 |
| 后端启动即报 `series_issues` | 离线缺观测 | 补 `observations.csv`，或加 `--tcp-port` 走在线 |

**单位**（内部全 SI）：压力 Pa（CSV `unit` 可写 MPa/kPa/bar/psi）、流量 m³/s（可用
`q_m3s` 或 `q`+`q_unit`）、渗透率 m²（`k0_md` 用 mD）、长度 m、时间 s。
