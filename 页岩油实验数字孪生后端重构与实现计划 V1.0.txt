# 1. 这轮修改中，真正做对了什么

首先值得肯定的是 sparse Newton 这条路线已经落地了。

现在 Jacobian 明确采用：

$$
J=
\begin{bmatrix}
J_{ff}&J_{fm}\\
J_{mf}&J_{mm}
\end{bmatrix}
$$

只保存：

* 同连续体相邻 cell；
* 同 cell matrix-fracture transfer；

不再构造 \(N_u^2\) 的 dense matrix。

线性求解也已经变成：

```text
小规模 → spsolve

大规模 → GMRES + ILU
```

而且上一版那个：

```python
line search failed
→ 强制走 0.1 Newton step
```

已经删掉，现在正确地抛出 `PhysicsConvergenceError`，由外层：

$$
\Delta t\rightarrow\frac12\Delta t
$$

重新算。

这一点非常重要。

# 5. 但是我发现：当前真正的性能瓶颈还没有解决

这是现在最重要的结论。

虽然 Jacobian 已经 sparse，但**Jacobian 的数值导数仍然非常贵**。

现在 `_coloring_jacobian()` 还是：

```text
for color
    for continuum
        for primary variable
            perturb
            full residual
            flash
```

目前 `_cell_colors()` 沿用原来的：

$$
3\times3\times3=27
$$

种颜色。

如果二元组分：

$$
N_c=2
$$

每个 continuum 的未知量：

$$
N_c+1=3
$$

于是一次 Jacobian 大约需要：

$$
27\times2\times3
=
\boxed{162}
$$

次 residual evaluation。

**每一个 Newton iteration 162 次。**

所以现在虽然：

$$
\text{sparse solve}
$$

已经很便宜，

但：

$$
\boxed{\text{Jacobian assembly}}
$$

依旧非常贵。

这也和仓库自己的 performance profile 一致：目前判断 flash + colored-FD residual 是主要成本，而 sparse solve 相对较小。

---

# 6. 这里有一个很大的优化机会：27-color 可以尝试降到 7-color

对 Cartesian 3D 7-point stencil，当前：

```python
(i % 3)
+ 3*(j % 3)
+ 9*(k % 3)
```

这种 27-color 是非常保守的 distance-2 coloring。

实际上可以构造 7-color，例如类似：

$$
c(i,j,k)
=
(i+2j+3k)\bmod7
$$

再严格验证：

> 所有会同时影响同一个 residual row 的 unknown 不得同色。

如果成立，那么 Jacobian residual 次数直接从：

$$
27\times2\times3=162
$$

降成：

$$
7\times2\times3=42
$$

理论上 Jacobian assembly 调用次数接近：

$$
\boxed{3.9\times}
$$

下降。

我认为这应该成为**下一轮第一性能任务**。

但必须有自动检查：

```text
verify_coloring_no_row_collision()
```

不能凭公式直接换。

# 7. 更关键的问题：刚加的 Flash Cache 实际没有作用在最贵的 Jacobian 路径上

这个我认为是当前代码里最值得马上修的地方。

你现在确实增加了：

```text
k_flash
p_flash
z_flash
```

缓存。

并且支持：

```text
previous K
stability bypass
```

这很好。

但是代码紧接着：

```python
jac_fd = cells is not None
```

然后：

```python
if (not jac_fd) and prev_p > 0:
    ...
    k_guess = ...
```

也就是说：

> **只要是 Jacobian finite-difference flash，就禁用 K reuse。**

偏偏 Jacobian 才是现在 Flash 被调用最多的地方。

所以现在实际是：

```text
普通 residual
    → 可能 reuse K

Jacobian FD
    → 不 reuse
```

而一次 Newton：

```text
普通 residual：1 次

Jacobian residual：几十到一百多次
```

所以优化命中了较小的部分，没有命中最大的部分。

---

# 8. 应该怎么改 Flash Cache

这里应该区分：

### K-value reuse

可以在 Jacobian FD 中使用：

$$
K^{old}
$$

作为 flash 的**初始猜测**。

因为只要最终 flash 收敛到同一个热力学解，它不改变模型，只改变收敛速度。

所以：

```text
Jacobian FD:
    allow k_guess
```

---

### Stability bypass

这个更加敏感。

Jacobian FD 时最好先：

```text
disable stability bypass
```

因为如果扰动后跨相态边界，而你直接认为还是单相，会污染数值导数。

所以应该：

```text
FD flash:
    reuse K       = YES
    skip stability = NO

normal Newton:
    reuse K        = YES
    skip stability = conditionally YES
```

而不是当前：

```text
FD:
    两个都 NO
```

---

# 9. 当前 Flash cache 还有第二个问题

每个 Newton iteration 的主 residual：

```python
_residual(...)
```

调用时：

```text
props_f=None
props_m=None
```

于是会重新创建：

```python
PhaseProps(...)
```

也就是说**前一个 Newton iteration 的 cache 并没有天然传入下一个 Newton iteration**。

所以真正应该持久化：

```text
props_f_cache
props_m_cache
```

生命周期至少覆盖：

$$
\boxed{\text{整个 timestep 的 Newton iterations}}
$$

而不是仅仅覆盖一次 `_coloring_jacobian()`。

正确结构应该是：

```text
begin timestep

flash cache
    ↓
Newton 1
    ↓ reuse
Newton 2
    ↓ reuse
Newton 3

end timestep
```

而不是：

```text
Newton 1 → 创建 cache → 丢掉
Newton 2 → 创建 cache → 丢掉
```

# 11. 而且 fast loop 说“不 Flash”，实际上最后还是 Flash 了

`TwinLoops.fast_step()`：

```python
pf, pm = step_frozen_pressure(...)
```

这一步确实没有 flash。

但是最后返回：

```python
dual_to_state(...)
```

而 `dual_to_state()` 内部又：

```python
flash_state(fracture)
flash_state(matrix)
```

两个 continuum 全部 flash。

所以：

```text
fast loop:
    no flash
```

这个设计目标目前实际上没有实现。

### 正确做法

fast loop 应该：

* 更新 \(p_f,p_m\)；
* composition 不更新；
* saturation 可以冻结上一次 slow full model 的值；
* UI 每秒输出压力；
* 饱和度注明为 last full-model state / held state。

而不是为了返回 `State` 又重新把 54,000 个 continuum cell flash 一遍。

# 12. frozen-pressure 还有一个物理问题：压缩性写死成 \(10^{-9}\)

现在：

```python
_C_PA = 1.0e-9
```

然后：

$$
A=
\phi V c/\Delta t
$$

这实际上人为决定了 fast-loop 压力传播速度。

这个不能最终保留。

应该在 slow full compositional solve 后计算：

$$
c_t^f(x)
$$

$$
c_t^m(x)
$$

或者更准确：

$$
\frac{\partial N}{\partial p}
$$

的局部 accumulation derivative，然后 freeze 到 fast window。

这样：

```text
full compositional model
     ↓
linearized pressure coefficients
     ↓
fast predictor
```

才是真正物理一致的 reduced model。

# 17. ProcessPool 也已经有了，但还有明显优化空间

现在每个 job：

```python

```

直接把整个：

```python

```

放进 payload。

这意味着多进程可能反复 pickle：

* grid；
* observations；
* context；
* EOS；
* ports；
* configuration。

尤其在 spawn 型 multiprocessing 环境下开销会非常明显。

更合理的是：

```text
ProcessPool initializer
    ↓
每个 worker 初始化一次 immutable TwinContext

每个 job:
    只传 theta
```

也就是：

```python
_pool_context = ...

def init_worker(context):
    ...

def run_member(theta):
    ...
```

不要每个 ensemble member 都重新序列化完整 twin。
